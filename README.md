# PDF重命名（PdfOcrRenamer）

面向电力业扩工程资料归档的 PDF 批量处理工具：**批量 OCR 识别标题并按映射规则重命名**、**整份扫描 PDF 自动拆分归档**。图形界面（CustomTkinter），无需命令行，Windows 下开箱即用。

## 功能特性

### 1. 批量识别重命名
- 递归扫描所选文件夹（含子文件夹）内所有 PDF
- 两阶段标题识别：先识别页面顶部标题，未命中时再尝试图纸右下角标题栏（竣工图纸）
- 按「识别内容 → 映射内容」规则匹配，OCR 错字自动容错
- 两种命名方式：
  - **仅按映射内容**：如 `开工报告.pdf`
  - **文件夹名+映射内容**：如 `模板工程A开工报告.pdf`
- 识别预览确认后再执行，可随时停止，**一键撤销**最近一次批量重命名

### 2. 整份扫描 PDF 拆分归档
- 以「开工报告」页为项目边界，自动把整份 PDF 切分为各个项目
- 从开工报告表格中 OCR 提取**工程名称**，自动匹配根目录下的项目子文件夹
- 单页资料直接拆分；多页资料（工作票、甲供物资超欠供表等）自动合并为一个文档
- 拆分模式下**命名方式可选**：
  - 仅按映射内容：文档仅用标题命名
  - 文件夹名+映射内容：匹配文件夹用「文件夹名+标题」，未匹配用「工程名称+标题」命名
- 未匹配到文件夹的项目归入 `未匹配项目/<工程名称>/`，原整份 PDF 保留不变
- 全部页面方向自动校正（纵/横/旋转），兼容竣工图纸的右下角标题栏
- 支持**一键撤销上次拆分**：只删除本次拆分新写出的文件，
  绝不触碰原整份 PDF 与其它已有文件（删除前有确认框）

### 2.1 资料完整性核对
- 以**项目进度表**为「应交」来源，以拆分输出目录为「实收」来源
- 自动检出三类问题：**缺失 / 多余 / 命名不一致**
- 支持导出 **Excel（总览 + 问题明细双表）** 或 **CSV**（UTF-8 BOM，Excel 打开不乱码）
- 同一资料的两种名字（映射内容 / OCR 识别内容）自动归一，避免误报「多余」

### 2.2 性能
- **页级 OCR 缓存**：同一份 PDF 二次分析耗时下降 **99%**（实测 328 秒 → 1.2 秒）
- 文件被修改后缓存**自动失效**（缓存键含文件大小与修改时间），不影响结果正确性
- 界面提供「缓存管理」入口，可查看占用并一键清空

### 3. 映射规则管理
- 首次运行自动生成内置默认规则（开工报告、竣工报告、接地电阻测试报告等）
- 界面内新增 / 删除 / 修改规则
- 支持从外部 Excel 导入（智能识别「识别内容 / 映射内容」表头，兼容多种格式）

### 4. 项目名称解析规则（可配置，不再硬编码地区）
- 拆分模式需要从开工报告表格中提取**工程名称**，用于匹配项目子文件夹
- 早期版本把「某省 / 某市 / 某县」「业扩配套工程」等地区与业务词写死在源码里，
  换地区或换业务类型后即失效。现已改为**配置驱动**：
  - 界面点「从进度表学习…」，选择含**项目名称**列的进度表 Excel，
    程序自动学习地域词、业务后缀与业务关键词并保存
  - 支持四种名称形态（中压业扩 / 资本打包 / 低压维修 / 项目包）
  - 配置文件：`%APPDATA%\PdfOcrRenamer\project_config.json`，可直接手工编辑
  - 不提供进度表时使用内置通用语法（不限定地域），同样可用

### 5. 使用体验
- 实时进度条 + 文件/页数显示，区分运行中与卡死
- 一键「停止」随时中止当前任务
- 规则与撤销日志保存在 `%APPDATA%\PdfOcrRenamer`，升级/重装程序不丢失
- 拆分时**首个开工报告之前的页面不会被丢弃**，统一落到
  `未匹配项目/_前置页面/` 供人工核对，避免资料丢失

### 6. 识别准确率（v3.3.0 重点修复）
- **修复竣工报告被误判为开工报告**：该缺陷会导致拆分时把 1 个项目切成 2 个、
  文件命名全部出错。经 30 页真实扫描件复现，根因实为**三层**
  （OCR 纠正表未接入匹配链路 / 模糊匹配平局取先遍历者 / 单页标题被 OCR 成残缺形态）。
  修复后真实样本项目数由 **4 个**恢复为业务的 **3 个**。
- **地域词容错**：真实扫描件中「某县」可能被识别为 甲县/乙县/丙县/丁县，
  现已能全部识别为同一地域（容错度可配置，默认允许 1 字不同）
- **修正 OCR 编号符号**：如「某堤口2**\***配变」（`*` 应为 `#`）此前会导致
  名称提取**静默返回空**，现已容错

## 系统要求

- Windows 10 / 11（64 位）
- 从源码运行需 Python 3.10+

## 下载与使用

从 [Releases](https://github.com/lzb354411/pdf-ocr-renamer/releases) 下载：

| 文件 | 说明 |
| --- | --- |
| `PdfOcrRenamer_Setup.exe` | 安装包，自动创建桌面/开始菜单快捷方式 |
| `PdfOcrRenamer_<版本>.zip` | 程序文件夹版，解压后运行 `PdfOcrRenamer.exe` 即可 |

使用步骤：

1. 启动程序，点击「浏览」选择包含 PDF 的文件夹
2. 选择处理模式（重命名文件 / 拆分整份PDF）与命名方式
3. 点击「① 识别预览」，确认预览结果
4. 点击「② 确认并执行」，完成后可在「规则管理」中调整规则重新识别

## 从源码运行

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 运行（Windows 下）
python src/main.py
```

## 打包 EXE / 安装包

```bash
build\build.bat
```

脚本依次完成：检查依赖 → 清理旧产物 → PyInstaller 打包（onedir，无终端窗口）→ Inno Setup 制作安装包（需安装 Inno Setup 6，否则仅生成程序文件夹版）。

## 数据与隐私

- 全部数据仅保存在本机 `%APPDATA%\PdfOcrRenamer`，不联网上传
- 映射规则文件：`%APPDATA%\PdfOcrRenamer\rules\PDFocr 映射规则.xlsx`
- 项目名称解析配置：`%APPDATA%\PdfOcrRenamer\project_config.json`
- 撤销日志：`%APPDATA%\PdfOcrRenamer\rename_log.json`（仅记录最近 20 笔）

## 项目名称解析配置说明

拆分模式依赖「工程名称 → 项目子文件夹」的匹配。工程名称由 OCR 从开工报告
表格中提取，其解析规则全部来自配置文件，源码中不含任何具体省市县名。

`project_config.json` 主要字段：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `region_words` | 地域词，用于定位名称起点 | `["某省某市某县", "某市"]` |
| `business_suffixes` | 业务后缀，用于定位名称终点 | `["业扩配套工程", "低压维修项目"]` |
| `valid_keywords` | 业务关键词（用于打分排序，非硬性条件） | `["业扩", "维修"]` |
| `noise_words` | 杂质字段，名称中不应出现 | `["建设单位", "计划开工"]` |
| `ocr_fixes` | OCR 常见错字纠正表 | `{"业扩配食工程": "业扩配套工程"}` |
| `folder_score_threshold` | 文件夹匹配相似度阈值（0~1） | `0.55` |

已支持的名称形态（均由真实业务数据归纳）：

```
中压业扩   某省某市某县3225000000000001某县某某建设发展有限公司10kV业扩配套工程
资本打包   某省某市某县2026年第一批包十0.4kV业扩配套
低压维修   2026年某县供电公司某某北北变台区低压维修项目3225000000000002
项目包     2026年某市某县低压台区维修项目包31
```

换地区 / 换业务时，只需点「从进度表学习…」导入新地区的进度表，
或直接编辑 `project_config.json`，**无需修改代码**。

## 常见问题

- **识别不到标题**：规则未覆盖该资料类型，在「规则管理」中新增「识别内容 → 映射内容」后重新识别
- **拆分后工程名称提取不到 / 项目进「未匹配项目」**：点「从进度表学习…」导入本地区的
  项目进度表（含「项目名称」列）以更新解析规则
- **重命名/拆分失败**：确认文件未被占用（如被 WPS/阅读器打开），或文件已被移动
- **撤销后文件名对不上**：请确认未在撤销前手动移动过文件
